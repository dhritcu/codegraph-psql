# tree-sitter-postgres.wasm and tree-sitter-plpgsql.wasm: provenance and rebuild

`src/extraction/wasm/tree-sitter-postgres.wasm` and
`src/extraction/wasm/tree-sitter-plpgsql.wasm` are built from
[gmr/tree-sitter-postgres](https://github.com/gmr/tree-sitter-postgres) at tag
`v1.2.4` (commit `9b27ba5c8700f9bf808221a0f6d17fe6515da787`) with
`tree-sitter-postgres.patch` applied. The patch touches `postgres/grammar.js`,
`plpgsql/grammar.js` and the PL/pgSQL corpus tests; every generated source is
regenerated by `tree-sitter generate`.

The repository holds two grammars. `postgres` is generated from PostgreSQL's
own `gram.y` and parses `.sql`, `.psql` and `.pgsql` files. `plpgsql` parses
the body of a `LANGUAGE plpgsql` function, procedure or `DO` block, which the
SQL grammar sees as one dollar-quoted string. It has no file extension; it is
loaded whenever `postgres` is.

## What the patch adds

Backported from upstream `main` (each one is a later upstream commit):

1. **`MERGE ... WHEN MATCHED THEN ...` without an `AND` condition**
   (upstream #80, `0b2c31176`). At v1.2.4 every `WHEN` clause required a
   condition, so the common form failed. The upstream commit also deletes the
   `[$.a_expr, $.a_expr]` conflict entry; that deletion is only valid for the
   PostgreSQL 19 grammar upstream moved to, and on v1.2.4 it makes
   `tree-sitter generate` fail with an unresolved `a_expr` conflict. The patch
   keeps the entry.
2. **String constants continued across lines** (upstream #83, `25228537e`):
   `'abc'` newline `'def'` is one constant in SQL, including for `E''`, `B''`
   and `X''` strings, with comments allowed between the parts.
3. **A positional parameter as a PL/pgSQL cursor** (upstream #85,
   `8477ac3c3`): `OPEN $1 FOR ...`, `FETCH $1 INTO ...`, `MOVE`, `CLOSE`.

New in this patch, all PL/pgSQL, none of them fixed on upstream `main` (`d6ba3d1`, 2026-10-20):

4. **Quoted identifiers.** The PL/pgSQL grammar had none, so
   `last_name TEXT COLLATE "C" := NULL;` (the Supabase storage migrations)
   failed. `quoted_identifier` is now one of the `any_identifier` choices, so it
   also covers quoted type names, cursor names and loop targets.
5. **An array suffix after `%TYPE` and `%ROWTYPE`** (PostgreSQL 17):
   `v%TYPE[]`, `v%TYPE[1][3]`, `v%TYPE ARRAY[1]`, `r%ROWTYPE[]`. Plain type
   names also take `ARRAY` (`integer ARRAY`).
6. **`FOR` targets qualified by a block label**: `<<lbl>> DECLARE a int; ...
   FOR lbl.a, lbl.b IN EXECUTE ...`. The label before the top-level `DECLARE`
   already parsed; the qualified targets it exists for did not. Qualified
   targets are a `qualified_identifier` node; unqualified ones keep their
   `any_identifier` shape.

Each new fix has a corpus test in `plpgsql/test/corpus/declarations.txt` or
`loops.txt`. `tree-sitter test` passes in both grammar directories (53/53
postgres, 84/84 plpgsql).

## Rebuild

```bash
scripts/grammars/build-postgres.sh [work-dir]
```

The script clones the pin with `GIT_LFS_SKIP_SMUDGE=1` (upstream's
`postgres/src/parser.c` is a 97 MB Git LFS object, regenerated here), applies
the patch, runs `tree-sitter generate` and `tree-sitter test` in both grammar
directories, writes both wasm files into `src/extraction/wasm/`, and prints
their sha256. It needs tree-sitter-cli `0.27.1` (it warns on any other
version), whose `build --wasm` fetches its own WebAssembly toolchain, so
neither emscripten nor Docker is needed. The postgres `generate` step takes
about two minutes; everything else takes seconds.
